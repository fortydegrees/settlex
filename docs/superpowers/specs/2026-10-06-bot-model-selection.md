# Approved bot model selection design

David approved a versioned model store with one current-selection file, after asking that compatible model promotion be essentially an upload and selection change. Implement in the existing isolated 008 branch; no public deployment, training, extra qualification games, dependency additions or unrelated dirty-checkout edits.

Use `.local/bot/current.json` by default locally, and the same `current.json` schema in an external production directory mounted read-only by web and game. `SETTLEX_BOT_MODEL_MANIFEST` overrides the location. Keep `release/bot-model.json` as the checked-in bootstrap/default metadata for existing setups, not the production upgrade mechanism. A selection has checkpoint, displayName, SHA-256, observationVersion/Dim, actionCount, mode and relativePath. Relative paths stay inside the selection directory, including symlink resolution when verifying actual model bytes.

Both app match labels and native worker startup consume the selection. A compatible future CTNN-v3 hash needs no source edits. The native loader verifies a supplied expected hash before parsing and still checks its fixed supported observation/action/topology contract and embedded probe. Existing sealed-model entry points remain for historical tests/direct callers; product operation always passes selected identity explicitly. Identity stays pinned across decisions and worker restarts.

`pnpm bot:promote -- --model FILE --checkpoint 008 --sha256 HASH [--directory DIR]` installs an immutable versioned model, verifies its expected hash and real native worker health, and atomically replaces current.json only after success. An existing model version with different bytes must never be overwritten. Failed validation leaves the selection unchanged. Switching back to an installed model performs the same verification and selection operation. No downloaded model or network operation is implicit.

Provide a production activation script using the already-built game image and a deliberate writable mount only for the promotion command. It stops web/game during activation, always restarts on failure, and restores the previous selection if activated-model preflight fails. Normal services retain read-only mounts. A future weights-only upgrade needs no image rebuild or public release counter change. The first infrastructure adoption needs the existing approved deployment workflow.

Selection is a startup snapshot; workers do not hot-reload mid-decision. Restart local game/web after changing selection; production script restarts both. Existing active matches can resume under the newly selected policy, as with the current release behavior; preserved match-name snapshots remain historical. No automatic per-match checkpoint retention is introduced.

Acceptance: filesystem validation/rollback tests, future-hash client and mismatch tests, Rust hash validation tests, real 008 activation then 007 rollback and return to 008, native setup/main-turn smoke, production script behavior with controlled Docker boundary, full pnpm verify, native build/tests/format/clippy, Docker image builds/preflight. Preserve research artifacts and 007 rollback.
