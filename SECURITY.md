# Security reporting

Do not post credentials, private match information or exploitable vulnerability
details in a public issue or pull request.

If this repository's GitHub Security tab offers **Report a vulnerability**, use
that private reporting flow. Its availability has not yet been verified for this
repository. If it is unavailable, arrange a private reporting channel with the
maintainer before sending sensitive details. There is currently no published,
verified security inbox or response-time commitment.

A useful private report includes the affected commit/version, a minimal
reproduction, expected and actual behavior, and the impact. Use synthetic
accounts and matches; do not test against other players or production data.

## Current preparation status

The cleanup branch contains security-related fixes and dependency updates that
have not been deployed as part of this programme. The hosted site and this branch
may therefore differ. Supported release versions and a private reporting channel
must be finalized before the public release announcement.

Maintainers: verify the private reporting channel, settle the supported-version
policy, and remove this preparation note only after those steps are complete.
Do not present a local test result or a clean secret scan as a guarantee that the
repository or deployed service has no vulnerabilities.
